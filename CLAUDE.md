# Working on NBA Fantasy RPG

- **Checks before committing:** `npx tsc -b`, `npx vitest run`, `npm run format:check`, and `npm run check:golden` (battle results must not change unless the change is meant to; re-record with `-- --update` only then).
- **Artifact:** after each change, `npm run build:artifact` and republish `dist-artifact/page.html` (with `assets/app.js`, `assets/index.css`, `data/2025-26.json`).
- **Docs:** keep `docs/design-doc.md` and `docs/backlog.md` current.
- **UI changes: check the teaching material too.** How to play and the Guide show the game, so a UI change can make them wrong:
  - **Sample turn** (`src/ui/SampleTurn.tsx`) draws with the real battle components (`EnemyCard`, `GoblinStack`, `HeroRow`), so it follows battle-screen changes automatically. Still read its step text (`src/ui/sampleTurnScript.ts`) against what the board now shows, and screenshot the steps.
  - **Coach tips** (`src/ui/coachTips.ts`) point at `data-coach="…"` elements; `tests/coachTargets.test.ts` fails if one disappears. Check that tip wording still matches the UI, and that each tip's `sheet` setting (action sheet closed or open) still shows what the tip points at.
  - **Basics cards, Glossary and setup banners** describe the UI in words: update them when a control, icon or flow they mention changes.
- **New content starts at the top.** `App` scrolls the page to the top whenever the screen (phase) or week changes. Inside a pop-up, when a tab, class or enemy picker swaps the content, use `useScrollToTop(key)` from `src/ui/scroll.ts` on the modal body. Exception: a picker in the middle of a page (the Progression tab's class picker) keeps its place.
- **Effects:** write `useEffect(() => { … })` with braces. The artifact frame's `window.scrollTo` returns a value, and an expression-bodied effect hands it to React as a cleanup, which crashed the game. `tests/effects.test.ts` guards this.
- **Branches and deploys:** work on `milestones-1-3`. The test artifact is https://claude.ai/artifact/2C61RY3DSCSKkhJZ4JKLoN (republish to that URL, don't make a new one). Friends play at https://vigabool.github.io/nbarpg/, which `.github/workflows/pages.yml` deploys on every push to `playtest`; push there (`git push origin HEAD:playtest`) only when the user says to ship to friends. CI (`.github/workflows/ci.yml`) runs on every push. The session container can't reach github.io, so check a deploy with `gh run list --branch playtest`, and have the user check the title screen's build label.
- **Saves:** a change to the shape of `SaveGame` bumps `SAVE_VERSION` in `src/app/saves.ts` and adds a migration to `MIGRATIONS`, with a test, so friends' runs keep loading.
- **Balance:** tune with the simulators (`npm run data:simulate`, `npm run data:season`, `npm run data:lair-combo`) before and after, and report the numbers. Difficulty multipliers live in `src/rules/difficulty.json`. New encounters follow `docs/adding-an-encounter.md`.
- **Browser checks:** Playwright needs `chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })` here; check UI changes on a phone-sized viewport (390×844).
